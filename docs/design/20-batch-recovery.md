# 批量运行、续跑与失败重跑

## 使用方式

新建批次的命令保持不变。配置中的 `max_concurrency` 控制同时处理的任务行数，默认 1，允许 1～16；一行内部仍依次执行出题、构建验证、审核。并发上限不代表已经验证机器或 API 可以承受该并发量。

```bash
sci-pipeline --config examples/pipeline/harbor.json --seeds examples/pipeline/seeds.jsonl
sci-pipeline --resume /绝对路径/原运行目录
sci-pipeline --retry-failed /绝对路径/原运行目录
```

此恢复格式用于本次更新后创建的批次；旧批次没有 `requests.json` 或准备阶段元数据时，会明确报错，不尝试猜测恢复。

恢复操作读取原目录中的 `run-config.json`、输入快照和任务清单，不重新读取原始种子表。继续使用原来的 `--env-file` 和 `--skills-root`；这些路径参与 Data Designer 的配置一致性检查。不要在同一批次中修改配置、输入快照或角色 skill。输入快照变化会拒绝恢复；需要变更资料或生成规则时，新建批次。

## 两种恢复方式

- `--resume`：继续当前提交。已有终态结果直接复用，包括失败结果；未完成任务复用已完成且文件校验通过的阶段，从尚未完成的角色开始。一个角色内部的 Codex 会话不会接着执行，该角色重新运行。构建阶段内部的单项自测不单独恢复。
- `--retry-failed`：批次结束后，选出所有非 `accepted` / `mock_completed` 任务，从出题开始重新运行。旧任务目录移入 `history`，成功任务不动。这里的失败包含 `failed`、`needs_materials`、`validation_pending`、`revision_limit`。如果任务尚未产生终态结果，先执行 `--resume`。
- 重跑过程再次中断，使用 `--resume` 继续这次重跑。
- 同一个运行目录有进程锁，不能被两个 CLI 进程同时处理。锁是本地文件锁，不是分布式调度系统。

## Data Designer 与任务阶段的衔接

Data Designer 保存每行的生成检查点（`buffer_size=1`），恢复时使用原提交目录和 `ResumeMode.ALWAYS`。首次生成使用 `NEVER`。每次失败重跑都有独立的提交目录，避免旧的失败行被 Data Designer 当成已完成行直接复用。

出题、构建、审核的检查点在角色返回并完成相应产物一致性检查后保存。续跑校验产物指纹；发现已完成产物被修改时，记录失败，不静默复用。尚未完成角色的残留产物归档后重新执行。真实 Harbor 任务重执行前会尝试清理该任务记录中可识别的容器资源，清理失败则停止该任务。

## 输入容错

每个非空 JSONL 行独立检查。JSON 不合法、字段不合法、路径不存在、缺少 `PACKAGE.md` 或复制失败，记录到 `input-errors.json`；其他正常输入继续执行。任务编号保留原始非空行索引，不因跳过错误输入而重新编号。

全部输入无效时，不调用 Data Designer，仍输出汇总并返回非零退出码。只要有无效输入或未通过任务，整批命令也返回非零退出码，便于自动化系统发现部分失败。

被输入检查排除的包没有任务记录，不属于 `--retry-failed` 的选择范围。修好这些包后，用仅包含它们的种子表新建批次即可。

## 主要产物

| 文件或目录 | 用途 |
|---|---|
| `requests.json` | 固定本批任务 ID、输入快照地址和 variant |
| `input-manifest.json` | 输入快照及内容指纹 |
| `input-errors.json` | 被跳过的输入与原因 |
| `active-submission.json` | 当前首次执行或失败重跑的任务选择 |
| `submissions/` | 各次提交的 Data Designer 数据与检查点 |
| `tasks/` | 当前任务结果与阶段检查点 |
| `history/` | 旧的失败任务与中断阶段产物 |
| `results.jsonl`、`summary.json` | 当前整个批次的任务结果和无效输入数 |
| `timing.json`、`invocations/` | 最近一次调用耗时及各次调用的耗时记录 |

不新增 API 请求速率限制、费用上限或按整机资源动态调度。以上机制解决运行恢复与单包隔离，不等同于已经完成 1000 包压力测试。

## 本次验证

本地 37 项测试通过，包含真实 Data Designer 调度与 mock 角色集成：完成第一行落盘后直接终止子进程，再从原目录恢复剩余三行；原第一行结果未被改写。另覆盖失败任务单独重跑、出题／构建阶段复用、产物被修改时拒绝复用、全部输入无效、错误输入不影响正常输入、同目录双进程锁。

测试不调用模型 API，不启动 Docker。当前沙箱中连最小 Python 跨线程异步唤醒示例也超时，因此集成测试在获准的沙箱外环境执行。尚未验证真实 Harbor 进程中断恢复或 1000 包压力场景。

## 执行生命周期衔接

续跑和两种失败重跑现在会先检查 `executions/` 登记，停止孤儿 worker、清理并复查所属容器后再调度。新增 `--cancel`、`--cleanup` 入口，取消请求与清理结果分别记录。详见 [执行生命周期](22-execution-lifecycle.md)。
